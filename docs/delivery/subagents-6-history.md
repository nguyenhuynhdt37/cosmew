# Durable task history and restart correctness

Implemented 2026-11-22 for contract 1.43 / SQLite schema 11 ([ADR 0089](../adr/0089-subagent-task-management.md)).

`SqliteBackgroundTaskHistory` owns shell snapshot writes in the existing private SQLite database. The CLI registry saves the original conversation owner and a redacted snapshot before completion delivery/observer publication. Snapshots preserve task ID, description, start time, status, exit code and output tail. Descriptions are at most 1,024 characters, tails at most 8,192; complete text is redacted before truncation and durable serialization. Retention is 200 snapshots per conversation and 5,000 across the database, newest updates first. Conversation deletion removes its archives in the same transaction. No new dependency is introduced.

After reopening SQLite and constructing a new registry, historical shell tasks remain inspectable through the existing background-task list. Stored running snapshots project to `stopped`; only a task owned by this registry and present in its live runtime can be stopped. Archived IDs, unknown IDs and other conversation owners cannot reach runtime stop controls. A live owned runtime snapshot takes precedence over archived data. History has no execution port and performs no automatic command replay, relaunch, resume or completion notification replay.

Agent history continues to use existing child conversation messages and execution journals. Inspection uses live scheduler state where available. A historical `running` child with no scheduler task projects to `interrupted` / `PROCESS_EXIT`, including metadata saved before a child turn began; wait returns promptly. Unfinished historical tool steps display as errors, not running tools. Reconstructed views retain at most 200 transcript steps and a 4,000-character final assistant summary. Explicit existing `agent_message` resume remains a separately authorized operation; reading history never invokes it.

The schema 10→11 migration adds `background_task_history` and its recency index without rewriting conversations or journals. Older binaries refuse schema 11 through their existing future-schema guard. Archives are snapshots, not full shell transcripts or OS reattachment records. A process surviving a CLI crash is not claimed as live or reattached; history cannot signal it.

Verification: `tests/contracts/background-task-history.test.ts` uses real file-backed SQLite, closes/reopens the database and constructs new registries/managers. It checks terminal status/output retention, redaction before writes, owner boundaries, unknown/archived stop refusal, live precedence, no execution/delivery during recovery, per-owner/global retention, deletion, migration/future-schema refusal, transactional failed writes, and child transcript inspection/wait with orphan metadata. No native sandbox or authenticated provider compatibility claim follows from these tests.
