# Task 03B — native supervision research

Accessed 2026-11-15. These sources describe mechanisms, not successful Hannes containment. No new native helper, dependency or platform backend was installed.

## Source inventory and limits

- Codex revision `ee344ca9458351a6ea102795fa73110ad3ede5dc`: [process groups](https://github.com/openai/codex/blob/ee344ca9458351a6ea102795fa73110ad3ede5dc/codex-rs/utils/pty/src/process_group.rs), [unified execution](https://github.com/openai/codex/blob/ee344ca9458351a6ea102795fa73110ad3ede5dc/codex-rs/core/src/unified_exec/mod.rs), [manager](https://github.com/openai/codex/blob/ee344ca9458351a6ea102795fa73110ad3ede5dc/codex-rs/core/src/unified_exec/process_manager.rs), [Linux sandbox](https://github.com/openai/codex/blob/ee344ca9458351a6ea102795fa73110ad3ede5dc/codex-rs/linux-sandbox/src/bwrap.rs). Audit reference: prepare policy/environment, launch sandbox, own child, request cancellation/stop, drain bounded output, release ownership. The group helper labels killing best-effort. Its macOS fallback enumerates members; neither mechanism reaches a child that has detached and reparented. This does not certify all upstream execution paths or import upstream PTY/session features.
- [Apple XNU event.h](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/event.h), moving `main` snapshot (exact revision not pinned; Needs verification for deployment): NOTE_TRACK/NOTE_TRACKERR/NOTE_CHILD are unsupported. Tracking ancestry would in any case be observation rather than an enforced lifetime boundary. Seatbelt's access restrictions do not establish kill-on-owner-death behavior. No unprivileged macOS lifetime container is demonstrated here. launchd/Endpoint Security deployment alternatives remain Needs verification; no claim of impossibility is made.
- [Linux PID namespaces](https://www.man7.org/linux/man-pages/man7/pid_namespaces.7.html), rolling manual: namespace init termination kills remaining namespace processes. A future backend must demonstrate namespace setup, sandbox enforcement and crash ownership on its real production path. No Linux runtime acceptance was run on this macOS host.
- [Linux cgroup v2](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html), rolling kernel documentation: inherited membership, `cgroup.kill` and `cgroup.events` populated state can support independent lifetime ownership. Hannes would still need trustworthy delegation, enrolment before executing adversarial code, no migration escape, stable identity and an external crash owner. Merely creating a cgroup does not kill it when a JS supervisor crashes.
- [PR_SET_PDEATHSIG](https://www.man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html), rolling manual: configured child receives a parent-death signal, but fork clears this setting for the new child. It is not arbitrary descendant containment.

## Decision

Keep production execution closed everywhere. Retain only best-effort group signalling while the owned leader has no observed exit; remove broad descendant enumeration from production. Bound local cleanup independently of descendant survival. Report leader exit, requested stop, output EOF/cutoff and unknown descendant termination separately. Numeric group signalling still has no kernel-stable identity proof; rapid-exit fixture coverage is evidence against specific regressions, not a PID-reuse proof. No permission/approval or isolation fallback is introduced.
