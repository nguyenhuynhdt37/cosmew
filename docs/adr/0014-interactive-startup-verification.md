# ADR 0014: Interactive folder consent and account verification

> Consent persistence is amended by [ADR 0075](0075-persistent-workspace-consent-and-claude-keybindings.md): the first approval is persisted per canonical workspace in user settings. The account/model verification described below still runs on every launch.

Accepted 2026-11-15 at the user's request. Applies to interactive FUTRYN TUI startup. PA1/TUI1/SUB1 scope, tool permission engine, and provider authentication boundaries remain unchanged; no new dependency or storage schema.

Before interactive chat or a requested initial slash command, show the current workspace and require an explicit session-only Allow selection; Exit is selected by default. File reference and diff views may read that folder after consent. This UI consent does not grant write/shell/tool permissions or replace the security permission engine. Denial/Escape/Ctrl+C exits without a provider request. Consent is not persisted. Non-TTY single-frame display remains noninteractive and exits without running chat.

After approval, check the selected account and model with a small generation request through the existing provider adapter; model-list endpoints may be public and cannot by themselves prove access. The consent screen discloses that this check may incur cost. This standalone probe is not included in a chat session usage total. When there is no active account, or verification fails, keep chat locked and offer saved accounts plus sign-in. Auth/forbidden failures are identified separately from retryable network/runtime failures. The picker initially focuses a different non-invalid account if one exists, otherwise it focuses sign-in; the failed account remains available for retry. Credentials are never deleted or silently switched, and failed checks cannot display success. Choosing another account checks it; a new login uses existing auth flows, requires model selection as needed, then is checked before entering chat. A model/account/auth-generation change during the asynchronous check forces a new selection/check. Escape/Ctrl+C aborts the check and drains it on shutdown. Cancellation does not claim that a remote request was undone.

SDK contract 1.5 adds an optional `generate` parameter to `diagnose(signal, generate)`; default behavior remains model-discovery diagnostics. Startup uses `generate=true` to validate the active model, retaining existing cache metadata rather than overwriting it with a less complete list response. Account selection and auth-generation fences remain in force. The check establishes only that the selected request succeeded at that moment, not future availability, subscription quota or permissions to all models. It can fail when a provider blocks small test generations or is unavailable; the user can retry or sign in to another account. No live-vendor inference was performed for this increment.
