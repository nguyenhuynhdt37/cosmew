# ADR 0066 — Claude Code fullscreen layout

Date: 2026-11-19. Status: accepted. Supersedes [ADR 0065](0065-inline-claude-code-layout.md) (inline layout, no alternate screen) and reinstates the alternate-screen decision of [ADR 0064](0064-fullscreen-ink-tui.md). No contract bump, no new dependency, no provider, persistence or security API change; only `apps/tui` and its tests.

## Problem

ADR 0065 made the interactive TUI inline because the reference capture it relied on showed Claude Code printing into scrollback. That capture was taken in a polluted environment: the reference process inherited `CLAUDE_CODE_*` variables from a nested session and fell back to inline mode. Re-captured in a clean PTY (100x30, Claude Code 2.1.328, macOS, 2026-11-19), the reference is a fullscreen alternate-screen application: banner on row 1 inside a scrolling transcript, composer and footer pinned to the last rows. A real user session screenshot (same day) agrees. The authoritative evidence is now `docs/delivery/tui-v4/reference/` and its reading in `docs/delivery/tui-v4/spec.md` (sections 1, 2, 5-7, 9).

## Decision

1. **Alternate screen.** On an interactive TTY, `runInkTui` renders with Ink 8's public `alternateScreen: true`. Ink writes `ESC[?1049h` on mount and `ESC[?1049l` on unmount; the existing exit path unmounts on a normal exit and on SIGINT/SIGTERM, and the resume hint is printed after the leave sequence so it stays on the main screen. Non-TTY runs stay one deterministic `renderToString` frame with no control sequences.
2. **Frame.** When the stream reports a positive `rows`, the shell is a column of that height. Top: a scroll viewport. Bottom, pinned, from the last row upward: footer line, blank line, optional warning line (`⚠ ...`), rule, composer, rule, right-aligned effort line (`◐ medium · /effort`). While a turn runs, the spinner line and a `⎿  Tip:` line sit directly above the effort line. The reference rows at 100x30 are fixed: effort 24, rules 25 and 27, prompt 26, footer 29. Without rows (ink-testing-library) the frame stays content-sized.
3. **Banner in the transcript.** The three-row Futryn glyph in the brand colour, `Futryn v<ver>` (bold), `<model> with <effort> effort · <account>` and `/…/<cwd tail>` are the first content of the scrollable transcript, below one blank row, and scroll away with it. The startup gate (consent, account check) is drawn at the top of the screen, as in the reference trust frame.
4. **Scrolling.** The viewport content is bottom-anchored by flexbox (a filler row absorbs spare space so short transcripts start at the top), clipped with `overflow="hidden"`, and shifted with Ink's public `contentOffsetY`. PgUp/PgDn page it (fn+Up/Down on macOS). When it is not at the bottom, a `Jump to bottom · fn+↓ to scroll` chip is drawn on the last viewport row; new output follows only when at the bottom and otherwise leaves the reader's position unchanged. Only the newest items (60, plus 40 per PgUp that reaches the top) are mounted. `<Static>` is not used in this tree (ADR 0064: Ink replays static output after every alternate-screen clear). Mouse wheel is not implemented: Ink 8 exposes no mouse events, and enabling terminal mouse tracking ourselves would need a new input layer (listed as a gap).
5. **Panels and dialogs.** An open panel or dialog replaces the composer and footer at the bottom of the screen; the transcript, subagents and notices stay mounted above it and are clipped first on short terminals, leaving at least one row. Panels (`/config`, `/status`, `/help`, `/permissions`, `/resume`, `/context`, `/memory`, ...) open with a full-width `▔` rule. Permission, question and startup dialogs open with a full-width `─` rule. Choices never scroll off: the dialog budget is `rows - 1`, and the shared Panel reserves controls before the body (the existing 80x12 case).
6. **Theme.** `auto` is the default again (a saved Dark/Light/Auto choice still wins). Auto picks light or dark from the terminal background: on a TTY the runtime sends OSC 11 (`ESC]11;?BEL`) before the first render and waits at most 150 ms for the answer (luminance of the `rgb:` reply); if the terminal does not answer it uses `COLORFGBG`, then `FUTRYN_THEME_MODE`, then dark. macOS `AppleInterfaceStyle` is never read. The light and dark presets use the values measured from the reference (spec section 9): brand `#d77757`; dim `#6e7171`/`#a9abae`; rule and spinner `#3465a4`/`#81a2be`; selection and plan mode `#05727e`/`#8abeb7`; path `#5769f7`/`#b1b9f9`; user message background `#f2f3f3`/`#353940`; panel background `#f5f5f5`/`#262626`; diff backgrounds `#e4f0da`/`#f7d9d9` (light) and `#3d423c` (dark add); warning light `#8e7700`. Surfaces use tokens only.

## Boundaries

`apps/tui` still depends only on the SDK. Slash-command behaviour, permissions, persistence and providers are unchanged. The tab bars inside `/config`, `/help`, `/permissions`, the 2-column slash menu, the footer wording (`⏸ manual mode on`) and the transcript glyphs (`⏺`, merged tool summaries, end-of-turn line) are later phases (G3-G5); the layout contract of this ADR does not depend on them.

## Evidence and limits

Frames compared line by line: `reference/idle-100x30/01-ready`, `02-shortcuts`, `03-slash`, `05-mode-*`, `00-trust`, `20-cmd-*`, `live-120x36/L09-pgup`; Futryn captures with the same harness are in `docs/delivery/tui-v4/futryn-g2/`. `apps/tui/src/ink/testing/fullscreen.test.tsx` renders real Ink frames on sized streams (rules on rows 25/27 at 100x30 and 31/33 at 120x36, footer on the last row, bottom block pinned while scrolling, panel and dialog rules, 80x12 permission choices with a transcript line above, spinner and tip above the effort row, alternate-screen enter/leave through `runInkTui`, OSC 11 light/dark/no-answer). `tests/end-to-end/tui-ink-pty.test.ts` and `apps/tui/src/ink/testing/native-pty.test.ts` drive a native macOS PTY through enter, leave and exit 0. Linux and Windows terminals, terminals that mishandle `ESC[?1049h`, and a live provider run are **Needs verification**. The dark `diffRemoved` background and the dark warning colour were not measured. This ADR does not claim Product MVP completion.
