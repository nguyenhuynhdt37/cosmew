# ADR 0009: Commands, observable request state and account continuation

Accepted 2026-11-15 following explicit approval to implement the command/usage/context audit, account switching with continued conversation and logout confirmation. Extends PA1/TUI1/SUB1 only; general execution, MCP/plugin hosts and delegated agents remain Not implemented. No new dependency or package edge.

Contract 1.3 adds optional model reasoning-effort metadata/preferences, a request effort field, reasoning-summary/usage/context stream events, validated turn receipts and optional receipt arguments to ConversationStore. CLI/core/models/security/persistence/SDK/TUI consumers migrate together. Settings schema 1 accepts optional reasoningPreferences; existing settings remain valid. Older strict readers cannot read new preferences, so downgrade is unsupported. Existing providers need not supply new events. New event consumers handle unknown usage explicitly.

SQLite migrates versions 0/1 to version 2 transactionally by adding turn_receipts. Pending user messages and initial receipts share a transaction; completion/interrupt and final receipt share a transaction. Existing sessions are not backfilled with invented counts. A receipt left pending by an unclean process exit remains explicitly pending/unfinalized; no successful completion is inferred. Reported usage/context observations are also persisted during the turn, so an unclean exit does not erase already observed counts. Newer storage versions fail closed. Usage has no prompts, credentials or reasoning text. Token cache/reasoning counts are subsets of input/output, never added to totals again. Cancellation/failure retains usage already reported; absent usage is unknown rather than zero. Price-derived cost is explicitly estimated, has metadata provenance, and is withheld for cache-bearing requests without cache prices. Subscription premium-request multipliers are not USD.

Provider-reported reasoning summaries are redacted through a separate streaming filter, bounded, and shown apart from the answer; raw private reasoning is not requested from Codex. Reasoning text is transient UI data, not persisted in receipts. Effort is exposed only when model discovery advertises supported values and checked at the transport boundary. Models without such metadata use provider defaults. Core does not execute tool calls.

Context UI separates local UTF-8/4-plus-overhead estimates, model limits/output reserve and historical runtime measurements. It does not call the estimator an exact tokenizer or use cumulative session spend as occupancy. Hidden runtime context precludes a precise current percentage. No heuristic-only hard rejection or auto-compaction is advertised; output reserve must fit a known window. A reviewed tokenizer and provider-specific preflight context API remain future improvements.

Commands share one metadata registry/parser; aliases resolve before argument validation. Autocomplete keeps the selected absolute row visible and executes that same command. `/switch` (alias `/account`) accepts account index/alias/ID; `/accounts` retains administration. Continuing a chat under another account requires an explicit UI confirmation that committed history will be transferred. Persistence creates a new account-bound session, copying only committed messages and no usage/permission grants; the old session is preserved. Failed target discovery leaves the current selection unchanged. `/logout` returns to a focused named-account confirmation; Cancel is initially selected. Failure to delete vault material is surfaced and retryable, never successful sign-out feedback.

Shared provider transports, endpoint policy, auth-generation fencing, vault scoping and permission denial remain unchanged. Deterministic tests and actual PTY checks are reported separately from authenticated vendor verification.

Follow-up 2026-11-15: `/effort [level|auto|status]` is canonical, with `/model effort` retained as a compatibility alias. TUI selection stages advertised values with Left/Right and saves on Enter, cancels on Esc; `/model` uses the same staged interaction for the highlighted model. Existing settings/request contracts and transport validation are unchanged. Unsupported Claude-only modes remain explicit diagnostics; this does not claim complete Claude runtime parity. See the updated acceptance report for upstream references and checks.

Reactive follow-up 2026-11-15: reuse existing reactive-event kinds to invalidate projections after state mutations and usage/context observations; no new event/schema/storage version. Per-turn fallback usage is cleared at selection boundaries, local context includes the answer streamed so far, and bound selection/session/effort changes are refused while sending. TUI thinking is visible by default and respects explicit collapse. The existing reasoningDelta channel also carries officially disclosed ACP text thought chunks; Codex continues to expose summaries only and now explicitly requests `summary: auto`. No raw private reasoning, persistence of thought text, new permissions or dependency edge is introduced.
