# ADR 0034 — Unified exec terminal: workspace-write, PTY sessions and Codex stdin/approval semantics

Accepted 2026-11-16 under the user's Task 02 instruction ("Port Codex CLI terminal / unified exec"). Baseline Futryn `dev` `9477700fd0f391ad5b0d30d4d38fe7dd84a6b542` plus the uncommitted Task 01 token-truncation fix (preserved, committed separately). Supersedes the "no host writes / no PTY" limits of [ADR 0032](0032-contained-command-sessions.md) for the Docker backend only. Native macOS Seatbelt, native Linux and Windows remain closed. This ADR does **not** claim full Codex parity; see "Remaining differences".

## Decision

### Backend and selection
`FUTRYN_COMMAND_BACKEND` = `auto` (default) | `docker` | `none`. `auto` selects the Docker backend whenever `/var/run/docker.sock` exists; otherwise the native runtime (macOS Seatbelt, still closed; Linux/Windows unsupported). Selecting a backend grants nothing: exposure still requires the real self-tests. Hermetic tests pin `none` via `tests/preload.ts`.

Self-tests (privilege/filesystem/network, detached-descendant lease teardown, and a new **workspace-write probe** that proves a real write lands on the host while `.env`, `.git` and Futryn state stay intact) run once per engine identity + image + runtime policy id. Evidence is cached in-process and, for 24 h, in `exec-runtime-proof.json` inside Futryn's state directory (which commands can never see or write). Engine identity is re-read at most every 15 s; any change re-runs the probes.

### Workspace-write (trust boundary: the container mount namespace)
- The canonical workspace root is bind-mounted at `/workspace`, read-only or read-write per the effective mode. No other host path is mounted (`HostConfig.Binds` must be empty; the full mount set is compared exactly before start).
- Masks recomputed from the live tree on **every launch** (no symlink following; bounded to 250 000 entries / 512 masks, beyond which launch fails closed): the top-level `.git` directory read-only; nested `.git` entries and a `.git` file hidden; secret files (`SECRET_FILE_RULES`, same table as the read tool) replaced by an empty read-only file; `.futryn`, `.hannes`, patch temporaries and Futryn's state directory replaced by an empty read-only directory. Masks cannot be removed or renamed (EBUSY), and their originals are unreachable.
- Docker follows symlinks in bind *sources*. The only workspace-sourced bind besides the root is the top-level `.git`, `lstat`-verified as a real directory immediately before `create`; every other mask is sourced from Futryn's private control directory. A session holding `.git` as a mountpoint cannot rename or replace it (EBUSY), so while any running workspace-write session lacks that pin, new launches hide `.git` instead of binding it (security review finding, 2026-11-16; regression test "B (mount sources)").
- Writes run as the workspace owner's uid/gid (no capabilities, no-new-privileges), so host ownership is preserved; a root-owned workspace is refused. Read-only commands run as 65534.
- Symlinks resolve inside the container: absolute host targets do not exist there, `..` reaches the read-only image root. New hardlinks to anything outside the workspace are impossible (EXDEV). Pre-existing hardlinks inside the workspace (e.g. a pnpm store) share their inode with the outside file — identical to Codex's path-based sandbox; documented, not blocked.
- `apply_patch`, `read`, `grep` and host git see the same live files; there is no snapshot copy any more (`captureExecutionSnapshot` stays in `@futryn/workspace`, unused by this runtime).

### Effective sandbox and approvals
Configured mode: `FUTRYN_SANDBOX_MODE` = `workspace-write` (default) | `read-only` (invalid ⇒ read-only). The effective mode is the configured one when the runtime enforces it, else read-only (stricter, never looser). It is shown in the approval and is part of the grant scope (`executionKey`), so a session grant from workspace-write never covers read-only and vice versa. Revalidation after approval rejects a configured-mode change ("sandbox policy changed"). Permission modes/rules still answer only `ask` decisions; network escalation is the `network.connect` capability with a `null` rule target, so Bash allow-rules and `auto` mode cannot approve it (`bypassPermissions` can, as for every capability).

### PTY and control protocol
Host → PID1 stdin is now framed JSON lines (`in` base64 bytes ≤ 8 KiB, `rs` resize, `int` interrupt, `eof`); child output cannot reach this channel. Pipe sessions keep node pipes with backpressure; PTY frames queue up to 8 MiB while the transport is blocked, beyond which bytes are dropped and the receipt reports `cut-off`. Each `exec_command`/`write_stdin` result reports only output produced since the previous call.

### Shell mode
TUI `!command` calls `FutrynClient.runShellCommand` → CLI `toolPort.invoke(exec_command)`: the same dispatcher, approval, audit and sandbox. It requires folder consent, renders a Bash card, and is not sent to the model.

## Contract and migration
Contract **1.16**: `CommandSandbox`, `CommandRequest.{sandbox,tty,shell,login}`, `CommandOutcome.sandboxDenied`, `CommandRuntimeCapabilities`, `CommandSessionInfo.{tty?,sandbox?}`, optional `CommandRuntime.{capabilities,resize}`, `ToolDispatcherOptions.sandbox`, `ApprovalRequest.{network,justification}`, SDK port `runShellCommand`. All additions are optional; pre-1.16 runtimes are treated as pipe/read-only. No SQLite schema change. New result code `SANDBOX_DENIED`.

Intentional behavior changes (tests updated with the reason inline): stdin polls/interrupts no longer prompt, while non-empty input still does (its grant now binds the session, not the text); `SIGINT` interrupts the session's process group instead of tearing down the namespace; masked secrets are present-but-empty rather than absent; `yield_time_ms` is clamped instead of rejected; `.git` is readable (read-only) by commands although the `read` tool still denies it.

## Remaining differences and risks
- **Not full parity.** Native macOS Seatbelt stays closed (no descendant containment — ADR 0022 reproducer); native Linux bubblewrap/landlock and Windows (restricted token / ConPTY) are not implemented. Linux hosts can use the Docker backend but were not tested here.
- Every command is a fresh container: separate commands cannot reach each other's servers on localhost, and shell state does not persist between commands (Codex runs host processes and supports shell snapshots). Command latency is 0.45–1.5 s (measured) versus near-instant native spawns.
- Lease: every session has a hard deadline ≤ 30 min (default 5 min); Codex keeps terminals until exit/eviction. Session cap 8 vs Codex 64 with LRU pruning.
- No `prefix_rule`, `require_escalated`, filesystem additional permissions, shell snapshots, `environment_id`, or network-proxy domain policy. Network escalation is all-or-nothing bridge networking (it can reach host services through the engine gateway).
- Nested repositories (submodules, vendored `.git`) are hidden, so git inside them fails; `git` at the top level is unavailable while an unpinned write session runs.
- `.git/config` is readable by commands (as in Codex); remote URLs with embedded credentials would be visible to the model. Output redaction covers only registered secrets.
- The derived git image is verified structurally (base layer chain + one layer + recipe label); the Debian package itself is trusted via apt signatures at build time.
- The persisted self-test proof trusts Futryn's state directory; an engine reconfigured without changing ID/version/security options/image within 24 h is not re-probed.
- Fixture models drive the end-to-end evidence; no real-model acceptance was run for this task.

## Follow-up hardening (second security review, 2026-11-16)
- Docker: `.git/config` and `config.worktree` are masked empty (git status/diff/log still work), so remote credentials are not readable.
- Docker: while another workspace-write session runs, PID1 verifies through `/proc/self/mountinfo` that every protected entry is a mountpoint before the command starts, closing the race where a concurrent session moves a directory holding a masked secret; mismatches fail as `SANDBOX_FAILED`.
- `write_stdin` input that the approval prompt cannot show in full (> ~850 characters) is refused, so consent always covers exactly what is sent.
- Superseded as the default backend by [ADR 0035](0035-native-sandbox-default.md) (native Seatbelt/bubblewrap); Docker remains selectable.
