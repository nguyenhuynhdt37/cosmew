# ADR 0008: Subscription authentication through official runtimes

Accepted 2026-11-14 following the user's explicit instruction to support subscription sign-in, superseding ADRs 0005/0007 only for these bounded provider integrations. General tool execution, MCP/plugin hosting and external subagent scheduling remain unimplemented. No package tree or language change.

Use official Codex App Server, Copilot CLI RPC and Gemini/Qwen ACP in private per-operation profiles. Each account has an independent credential snapshot in the OS vault; never import another application's home/auth cache. Restore only allowlisted credential files into a private ephemeral directory, run fixed argv without a shell in an empty working directory, capture rotated credentials back into the vault, and remove the ephemeral profile on shutdown. Stale-operation auth generation fencing applies before/after each operation. Runtime subprocesses are provider transports, not a new delegated task scheduler.

Security owns fixed recipes, minimal child environments, runtime prerequisites and denial of all runtime-requested tools/permissions. Codex uses read-only sandbox, no shell/web/MCP/plugins/apps/agents and declines approval requests. Copilot uses an empty available-tools list and denies permission requests. Gemini uses tools.core=[] and disabled hooks/extensions; Qwen uses explicit deny rules and a nonempty impossible core allowlist (empty coreTools enables defaults). ACP client filesystem and terminal capabilities are never offered. No unmediated shell/filesystem operations are exposed. Unsupported protocol/control versions fail closed; process isolation alone is not advertised as an OS sandbox.

Contract 1.2 adds optional provider runtime identity, runtime credential references and automatic/polling auth challenge metadata/ports. An additive runtime_leases table serializes rotating credential use across processes with owner/PID fencing and dead-process reclamation inside SQLite transactions. Existing schema-1 rows remain valid; no existing row is rewritten. Runtime refs are new data: older contract readers fail closed. Multi-account auth state, refresh and local logout use the same generation fence as API accounts. The OS vault is mandatory; there is no persistent plaintext fallback. Official runtimes may materialize credentials in private transient files while running; crash remnants are a documented limitation requiring cleanup.

Claude subscription sign-in is not offered without Anthropic approval; API key access remains supported. Missing CLI installations produce explicit prerequisite diagnostics, never successful mock authentication. Live subscription/model entitlement needs the user's sign-in; deterministic subprocess protocol fixtures do not establish vendor compatibility. Research and acceptance are tracked separately.


## UX follow-up in the same increment

The user rejected the initial account-name prompts and split API/subscription provider rows. Registry family metadata now groups each vendor once and methods carry their target provider identity. Sign-in starts immediately after method choice; account aliases are generated, with optional rename later. Device-code and environment alternatives are secondary options. Login modal background covers the underlying composer/sidebar, sizes to content and preserves the draft. Browser startup itself is cancellable; account rollback/profile cleanup drains before shutdown. No arbitrary OAuth-client/endpoint/token fields enter the ordinary login flow.
