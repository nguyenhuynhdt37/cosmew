# ADR 0010: Selectable terminal text and complete user logout

Accepted 2026-11-15 following the user's requests for mouse text selection, visible used/total context, removal of successfully logged-out identities and no repeated activation of the current account. PA1/TUI1/SUB1 boundaries remain unchanged. No dependency, package edge, general shell/filesystem tool or plugin capability is added.

Contract 1.4 changes the SDK `logoutAccount` default to remove the local account after successful credential deletion. TUI logout/account-action logout and CLI user logout use removal. Consumers/tests migrate together; SQLite schema 2 and settings schema 1 remain valid. The lower-level AccountManager retains explicit non-removing logout for in-place reauthentication and failure fencing. Deletion fences the identity first, deletes the vault entry, then removes account/preferences. If vault deletion fails, the fenced record remains reachable for retry. Existing fenced rows are never silently discarded without successful cleanup. Conversations/usage history are not erased or rebound to newly created identities.

Provider/runtime context measurements can supply the model's observed window when discovery omitted it. The SDK records an observed limit only in an existing matching account/model cache after checking the account remains present and not logged-out. Runtime catalog refresh preserves such an observed limit if the new catalog still omits it. Context UI prefers measured used/total when the current turn supplies it or the completed history has no new draft; the label identifies a measurement. Otherwise it displays a marked local estimate. Output ceilings and output reserves remain distinct. No limit is inferred from a model name or copied between accounts.

Activating the current account is a no-op in SDK/manager/UI: no session reset, discovery or configuration write. The switch picker marks and skips its disabled active row and initially selects another account. Explicit switching to another identity remains cancellable and may return to previous accounts without logging them out. Tests cover repeated/no-op activation and A→B→A→B continuation.

Text selection belongs to the TUI presentation layer. SGR mouse down/drag/release selects visible, already redacted/masked framebuffer cells. A frozen view prevents animation or arriving tokens from replacing selected text; generation continues normally. Esc clears selection, and resize/other interaction invalidates its coordinates. Clipboard writes occur only on an explicit Ctrl+C/Ctrl+Y action using bounded OSC 52 payloads (64 KiB text maximum); there is no clipboard read, automatic copy, shell subprocess or raw credential access. Monochrome terminals use inverse-video highlighting. Shift+drag remains the terminal's native-selection fallback.

A bounded streaming input decoder preserves fragmented mouse/CSI sequences and UTF-8 input. Isolated Escape is resolved after a short delay; expired/malformed sequences cannot become draft text. Terminal input timers, mouse modes, selection and queued clipboard payloads are cleared/restored on shutdown. OSC 52 support is controlled by the terminal/host; a PTY can verify the emitted copy request, not prove an OS clipboard changed. Native GUI/clipboard acceptance is reported separately.
