# ADR 0025 — Approved workspace patches

Accepted 2026-11-15 by the user's apply_patch implementation request. Contract 1.10 adds `fs.write` to tool capabilities; ToolPort/ToolResult/message/DB schemas are unchanged. SDK permission input adds optional diffPreview; ConversationStore.interrupt adds optional appliedSteps so completed write receipts survive cancelled/failed model continuation without replay. Existing implementations remain source-compatible; the built-in SQLite consumer stores these pairs atomically with the interrupted turn receipt, without a schema migration. Consumers migrate together; older strict capability readers require upgrade before exposure.

`ApplyPatchHandler` parses Codex Add/Update/Delete/Move syntax, verifies all source snapshots, contextual replacements and destinations, and generates a bounded unified diff. `ToolOrchestrator` authorizes the whole exact patch with the existing prompt/grant/audit/cancellation path, then revalidates route, policy, grant and snapshots. Exposure is never authority. `ApplyPatchRuntime` applies through workspace-owned `SecureFiles`, returning actual per-path actions/hashes/diffs, created directories, remaining paths and partial-failure cause. Moves are a destination add followed by source delete; no multi-file rollback or transaction is claimed. Applied records are not cached as read-only results.

Filesystem traversal uses Bun's built-in FFI to trusted system libc openat/mkdirat/linkat/renameat/unlinkat with directory descriptors and no-follow opens, exclusive staging and atomic per-file replacement. Sources must be regular single-link UTF-8 files; secret-looking files, .git, Hannes state, traversal, symlinks, hardlinks and path collisions are denied before approval. Stale content/identity/ancestor changes invalidate the plan. No shell/helper/dependency is installed. Same-user privileged host tampering is outside isolation guarantees: this is not a sandbox against a hostile host, nor an atomic content CAS with external writers. No async yield occurs between final revalidation and filesystem operations.

The tool is exposed as a supported JSON function `{patch:string}` to direct providers and Codex dynamic tools. No freeform transport is advertised; native Codex file-change requests remain declined with its read-only runtime sandbox unchanged. Approval shows the sanitized/redacted diff and binds the full raw plan hash; session scope covers only the exact plan and original versions.

Limits: 64 KiB patch, 32 operations, 1 MiB per UTF-8 source, 4 MiB aggregate verified contents, 8 KiB aggregate paths, 50 KiB full approval diff and bounded matching work. Split larger patches; existing Add/Move destinations and overlapping paths are rejected. Missing parent directories can be created after approval and are included in failure receipts. No binary edits, environment selection, overwrite-on-add or unbounded freeform input. Large encoded result diffs may be omitted explicitly while retaining all action/hash/failure metadata. macOS OS acceptance is run locally; Linux glibc backend requires platform CI; other hosts do not expose the tool.
