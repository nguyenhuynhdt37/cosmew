# ADR 0011: Three monochrome appearances

Superseded for names and semantic colors by [ADR 0012](0012-theme-naming-and-semantic-colors.md).

Accepted 2026-11-15 at the user's request. Supersedes ADR 0006's user-facing multicolor catalog, live wallpaper selection and custom-theme editor. PA1/TUI1/SUB1 boundaries and existing security policies remain unchanged; no dependency or storage schema is added.

Appearance profile semantics version 2 has three choices, all using the same complete 30-token grayscale palette: `futryn-default` follows detected system/terminal appearance, `monochrome-dark` is light text on black, and `monochrome-light` is dark text on white. Mode and theme ID are saved together. `/theme` previews selection; Enter commits and Esc cancels. `themes set dark|light|system` and `themes mode dark|light|system` are supported. The CLI and slash editor/import workflows provide explicit unsupported diagnostics instead of implying a custom palette can be applied. Old built-in color and live-theme presets are removed from the catalog; wallpaper compositing is disabled in this profile. Mascot animation and other unrelated display settings remain available.

Migration: existing schema-1 appearance records are read without a data-schema upgrade. If the selected theme or wallpaper is retired, normalize the active global and current-project overrides separately to the monochrome ID matching their existing dark/light/system mode and clear the wallpaper selection. Other settings remain intact. User-owned custom-theme files are retained on disk; they are not offered as active appearance choices. If a settings write fails, use the correct grayscale palette in memory and report a warning; never delete theme files during startup. Custom imports are no longer accepted through the CLI, but existing format-conversion code remains for compatibility and security checks.

System detection prioritizes the terminal's `COLORFGBG` background hint and `FUTRYN_THEME_MODE` override; on macOS it reads `AppleInterfaceStyle` using the native `defaults` utility without a shell. A running TUI rechecks the preference every five seconds while system mode is active. Without a recognized terminal/environment hint on other platforms, the current fallback is dark; it does not claim complete desktop-theme integration. `NO_COLOR` remains under terminal control. Terminal and OS appearances can differ, so terminal background hints take precedence. Explicit dark/light modes do not follow system changes.

The semantic `ThemeTokens`/`AppearanceConfig` schemas remain unchanged; the three built-in IDs and profile behavior are the versioned compatibility change. Existing consumers, CLI help and tests migrate together. Manual live-terminal appearance still depends on the emulator and host palette.
