# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Cosmew is a TypeScript + Bun coding agent aiming at Codex / Claude Code / OpenCode parity. Any feature serving that goal may be built without per-feature authorization; record large design decisions as ADRs in `docs/adr/`. Implemented today: provider/auth (API adapters only; no external agent runtime), the COSMEW TUI, the Codex-parity agent loop, workspace tools (`read`, `glob`, `grep`, `edit`, `write`, `apply_patch`, `exec_command`, `write_stdin`), durable recovery/compaction, extended read/media/notebooks/nested instructions, durable plans and interactive questions, sandboxed LSP/rename, public web search/fetch and the MCP HTTP search adapter (wave 1/2 + P3 SDK; contract 1.40 / SQLite 10). Subagents (contract 1.34, ADR 0058, S5a-S5c done): `agent` (sync or `background: true` with a durable `<subagent>` notification to the parent), `agent_message/agent_wait/agent_close`, custom agents from `.cosmew|.claude|.agents/agents/*.md` and `~/.cosmew|~/.claude/agents` (untrusted data: catalog via user-context `contextNotes`, body only in the child's context, `tools` only narrow), `/agents`; `isolation: "worktree"` (host-created Git worktree under the OS temp dir, child writes only there, deleted when unchanged else kept and reported), children inherit the parent turn's caps and refuse with `AGENT_BUDGET_EXHAUSTED` once spent, optional `[agents] max_child_*` ceilings, `cosmew exec` waits for background children. Commands that run without the sandbox (`dangerouslyDisableSandbox`, an excluded command or `sandbox.enabled: false`) use the real HOME and host environment (Codex shell_environment_policy: `*KEY*/*SECRET*/*TOKEN*` and `COSMEW_*` dropped); sandboxed ones keep the scratch HOME. Not yet built: remote/cloud agents, agent teams, Codex-style TOML agent roles / child mailbox (docs/delivery/wave-2/deferred.md), plugins, GUI. User MCP (ADR 0068) is a slice: stdio and HTTP from the user mcp.json, listed by `cosmew mcp` and `/mcp`, called through ToolDispatcher. OAuth, project MCP config, tool_search, mcp_resource and registry install are not in that slice. The 0-byte placeholders (`packages/extensions`, `compat-*`, `testkit`, `apps/{server,web,desktop}`, and unused stubs inside real packages) were removed; the architecture docs keep the plan. Never claim "Product MVP complete": live authenticated generation is not verified.

`AGENTS.md` (Vietnamese) holds the agent rules. Permissions follow the Claude Code CLI ([ADR 0061](docs/adr/0061-claude-code-permissions-and-sandbox.md)): modes `default` / `acceptEdits` / `plan` / `bypassPermissions`, Claude-style settings files (`~/.cosmew/settings.json`, `<project>/.cosmew/settings.json`, `settings.local.json`; repository files are untrusted until the user approves their content hash) and a sandbox with a domain-filtering network proxy. The Codex model of ADR 0053/0055 (sandbox modes x approval policies, presets, `require_escalated`, `sandbox_mode`/`approval_policy` config) is gone.

Terminal execution ([ADR 0034](docs/adr/0034-unified-exec-terminal-parity.md), [0035](docs/adr/0035-native-sandbox-default.md), [0061](docs/adr/0061-claude-code-permissions-and-sandbox.md)): `exec_command`/`write_stdin` use regular permissions by default (sandbox off; ADR 0081), with an optional native OS sandbox (macOS Seatbelt; Linux bubblewrap, untested, no network there; Windows refused), `COSMEW_COMMAND_BACKEND=none` disables commands. The Docker backend was removed ([ADR 0062](docs/adr/0062-remove-docker-command-backend.md)). Sandbox: live workspace plus `permissions.additionalDirectories` writable, `.git` and Cosmew state never writable, reads everywhere except deny rules, a default sensitive list (`~/.ssh`, `~/.aws`, keychains, browser profiles, `~/.cosmew`) and secret-named files under home; no direct network, only a Cosmew-run loopback proxy that allows `sandbox.network.allowedDomains` and asks about new domains. `sandbox.autoAllowBashIfSandboxed` (default false) lets sandboxed commands skip the Bash prompt; `sandbox.excludedCommands` run outside the sandbox through the normal flow; `dangerouslyDisableSandbox` (replaces `require_escalated`) always asks. Secrets in the project stay readable unless `COSMEW_SANDBOX_HIDE_SECRETS=1`. macOS cannot confirm `setsid` descendants die (reported `unconfirmed`). A failing sandbox never falls back to unsandboxed execution. Hermetic tests pin `COSMEW_COMMAND_BACKEND=none` (`tests/preload.ts`); Docker tests need `COSMEW_TEST_CONTAINER=1`.

## Commands

Requires Bun 1.4.4. No build step; Bun runs the TS workspace directly.

```sh
bun install --frozen-lockfile --ignore-scripts
bun run cosmew            # canonical CLI (apps/cli/src/index.ts); bare TTY opens TUI
bun run hannes            # compatibility alias; `cosmew tui` opens the Ink TUI
bun run typecheck         # tsc --noEmit
bun run lint              # tsc with noUnusedLocals/Parameters + prettier --check + git diff --check
bun run format            # Prettier 3.9.10 (.prettierrc.json) on all .ts/.tsx/.js; run before committing
bun test tests            # all tests
bun test tests/contracts/theme-engine.test.ts          # single file
UPDATE_GOLDEN=1 bun test apps/tui/src/ink/testing/composition-golden.test.tsx   # re-record Ink golden frames; review the diff first
bun test tests/contracts -t "name substring"           # single test by name
bun run test:integration  # provider adapters + tests/security
bun run test:e2e          # tests/end-to-end (PTY/CLI flows)
```

Optional, touches real OS keyring / network (opt-in via env): `COSMEW_VERIFY_KEYRING=1 bun scripts/verify-keyring.ts`, `COSMEW_TEST_KEYRING=1 bun test tests/end-to-end/provider-cli.test.ts`, `COSMEW_LIVE_PUBLIC=1 bun scripts/smoke-public-catalogs.ts`. `model doctor --generate` makes a billable request.

## Architecture

Workspace packages (`@cosmew/*`, resolved via bun workspaces, `moduleResolution: bundler`): `contracts`, `models`, `security`, `persistence`, `core`, `sdk`, `tools`, `workspace`, `code-intel`, `mcp`, `apps/tui`, `apps/cli`.

Dependency rules ([docs/architecture/dependency-rules.md](docs/architecture/dependency-rules.md)) are a DAG enforced by review, not tooling:

- Every package may depend on `contracts`; `contracts` depends on no Cosmew package and exports no foreign SDK types.
- `core`, `models`, `security`, `persistence`, `sdk`, `workspace` depend on nothing else in Cosmew. They meet only through injected ports. `tools` may depend on `workspace`, `security` and `code-intel`; `code-intel` may depend on `workspace`. `mcp` is a transport adapter injected by the CLI; tools never imports its implementation.
- `apps/tui` depends on `sdk` only (UI talks command/event protocol). `apps/cli` is the **composition root**: it is the only place that wires models + security + persistence + core + tools + workspace + tui (`apps/cli/src/bootstrap/startup.ts` builds the `Application`).
- Never deep-import another package's `src/` files; use its `index.ts`. Public contract changes need an ADR + migration/versioning + consumer updates.

Ownership: `core` orchestrates (agent loop in `packages/core/src/agent`, context builder); `security` decides permissions, holds secrets/OAuth and audit; `persistence` owns all durable SQLite writes (`~/.cosmew/provider-auth.sqlite`, with legacy roots supported); `models` only adapts provider wire formats (`adapter.ts`, `http.ts`, catalog, limits); adapters convert, never decide.

Credentials: API keys live in separate OS keyring entries or as environment-variable _references_; there is no plaintext fallback. Failed/cancelled logins must remove stored credentials. Account/provider switching starts fresh context (see ADR 0009 for the continuation rules).

Provider sign-in and execution ownership ([ADR 0045](docs/adr/0045-remove-delegated-and-chat-only-runtimes.md)-[0049](docs/adr/0049-remove-codex-runtime.md)): Cosmew only calls provider APIs and reads responses; every model runs the Cosmew agent loop with Cosmew tools (`executionBackendFor`: `hannes`, or `chat-only` without folder consent). No external agent process exists: no `delegated`/`codex-bridge` backend, no Codex/Copilot/Gemini/Qwen/Grok runtime (v7 and v8 migrations delete their accounts and credentials; startup deletes leftover `runtime-tmp`). A provider stream can never report a tool result. ChatGPT signs in only through the direct API (`apps/cli/src/subscriptions/chatgpt-oauth.ts`, OAuth + PKCE, tokens in the keyring; live behavior unverified). Any other endpoint is added by the user-level `~/.cosmew/config.toml` `[model_providers.<id>]` (Codex field names; parsed in `packages/models/src/host-config.ts`, loaded by `apps/cli/src/bootstrap/host-config.ts`; never read from a workspace, no plaintext tokens, token command without a shell). `status().toolsEnabled`/`availableTools()` are true only when the backend runs Cosmew tools.

TUI (`apps/tui/src`, [ADR 0059](docs/adr/0059-ink-tui-foundation.md) / [0060](docs/adr/0060-ink-tui-integration-and-memory-write.md); [ADR 0066](docs/adr/0066-claude-code-fullscreen-layout.md); spec and evidence in [TUI v4](docs/delivery/tui-v4/spec.md), G3 status in [g3-status.md](docs/delivery/tui-v4/g3-status.md)): React/Ink (pinned `ink` 8.0.0) is a Claude-Code-style fullscreen app on the alternate screen: scrolling transcript (banner inside it, PgUp/PgDn, `Jump to bottom` chip) above a pinned bottom block (effort row, rules, prompt, footer `⏸ manual mode on`, spinner + `⎿ Tip:` while a turn runs); panels (`▔` rule) and permission/question dialogs (`─` rule) replace the composer while the transcript stays visible. It is the only TUI for `fyn`, `cosmew`, `hannes`, `hannes tui` and bare runs; there is no `COSMEW_TUI` switch and no legacy renderer. Non-TTY runs print one deterministic frame. `runInteractiveTui` (`src/runtime.tsx`) -> `ink/runtime.tsx` -> `InkApp` (`ink/app.tsx`: SDK client, theme and overlay providers) -> `IntegratedShell` (`ink/integrated-shell.tsx`), the only owner of SDK tasks (turns, steer, slash commands, startup gate, permission/question dialogs, shutdown). Each function lives under `ink/features/<name>/` (`index.tsx` view/hook, `logic.ts` pure code, tests beside it); shared components in `ink/ui/`, hooks and keymap in `ink/hooks/`, the overlay router in `ink/core/`. Dialogs are opened through `useOverlay`; a feature never imports the app and never starts a second agent loop or grants a permission itself: everything goes through `@cosmew/sdk` (`CosmewClient`, `parseSlashCommand`/`SLASH_COMMANDS`, the memory write API that goes through the dispatcher). Kept from before: the theme engine (`src/theme/`, `ThemeEngine`, `./theme` export), `input/text.ts`, `clipboard.ts`. Transcript items record `parts` in arrival order and render `❯ prompt` (user background), `⏺ answer`, merged dim tool summaries (`Read 1 file`, `Ran 1 shell command`) and `⏺ Update(path)` + diff for edits; Ctrl+O (`useDetailedTranscript`) switches to the detailed transcript (`⏺ Bash(cmd)` + output, `<time> <model>` before answers, composer replaced by its footer), `!cmd` shell calls always show their output, a finished turn ends with `✻ <verb> for 8s · done 11:00 PM`, and finished slash commands leave `❯ /cmd` + `⎿ result` in the transcript (`transcript.addCommand`, `/context` prints its grid there; Esc on a panel prints `⎿ <noun> cancelled`). A streaming item shows only a viewport tail until it completes. Shortcuts that need the terminal use Ink's `suspendTerminal` (Ctrl+G edits the draft in `$VISUAL`/`$EDITOR`, Ctrl+Z stops the process); Keys go through one central keymap (`ink/hooks/keymap/`: Claude Code-style contexts and action ids, chords with a 3 s timeout, reserved Ctrl+C/D/M/[/I/H) that user-level `~/.cosmew/keybindings.json` overlays and hot-reloads (`/keybindings` creates and opens it; status in [keys-status.md](docs/delivery/tui-v4/keys-status.md)); `?` and `/help` are generated from it and include image paste and background task keys (fast/thinking toggle and `/btw` remain unsupported); Ctrl+C clears text first, then asks `Press Ctrl-C again to exit` (800 ms); Esc Esc on an empty prompt opens SDK checkpoint rewind (code/conversation restore and model-written summarize with optional focus). `/permissions` with nothing pending manages the session mode and the Allow/Ask/Deny rules of each settings file (`Bash(npm test:*)`, `Read(src/**)`), and approves pending repository settings; deny > ask > allow > mode (`plan` refuses edits and commands before allow rules). Slash commands are canonical per ADR 0013 (`SLASH_COMMANDS`, routed by `ink/features/commands.ts`); unsupported backends must print an explicit "Not implemented" diagnostic. P3 ([ADR 0074](docs/adr/0074-p3-review-and-session-controls.md)) adds Current/Uncommitted/Branch diff sources (Ctrl+X B), selective queued-text retraction preserving shell entries, atomic plan approval with feedback and durable editable markdown copies (Ctrl+G), summarize rewind, session-only model/effort (`s`), and timestamped prompt history scopes (Ctrl+S in Ctrl+R). The diff side panel opens from 110 columns. Fast/thinking toggles have no provider contract and remain unsupported; native clipboard remains Needs verification. Tests: Ink components with `ink-testing-library` (`ink/testing/`), real-SDK flows with `ink/testing/ink-session.tsx` (`openInk`, used by `tests/end-to-end/*`), and native PTY in `tests/end-to-end/tui-ink-pty.test.ts`; golden frames live in `ink/testing/golden-ink/` (`UPDATE_GOLDEN=1`, review the diff first). The Welcome and header use the Cosmew mascot, which freezes under Reduce motion. The legacy sidebar, wallpaper overlay, theme editor, command palette and mouse text selection are listed in `docs/delivery/tui-v3/parity.md`.

Prompt editor ([ADR 0091](docs/adr/0091-vim-prompt-editor.md)): `/config` → `Editor mode` switches live between
`normal` (the default editing keys) and `vim`. The user settings store saves `editorMode` in
`~/.cosmew/settings.json`. The `Vim` keymap context owns modal commands and Esc.
[Bindings and upstream evidence](docs/delivery/tui-v4/vim-mode-parity.md).

Tools (TOOLS1): `core`'s `Conversation` runs the Codex-parity loop ([ADR 0033](docs/adr/0033-codex-parity-agent-loop.md); no default round/call ceiling per ADR 0030, only user budgets and named safety limits) over an injected `ToolPort`: complete tool calls are dispatched while the response streams, shared/exclusive by the descriptor's explicit `parallel` flag (`core/agent/tool-runtime.ts`), and results are recorded in model-output order; `Conversation.steer`/`CosmewClient.submitWhileBusy` queue durable user input into the running turn (preempting the response being sampled; input a turn cannot deliver carries into the next turn), and sends shared exploration guidance from `core/agent/guidance.ts` via `ModelRequest.instructions` (system/developer channel; never repository text). `@cosmew/tools`' `ToolDispatcher` is the only enforcement point: validate → `@cosmew/workspace` normalizes paths in the project, trusted additional directories or an external per-operation root ([ADR 0092](docs/adr/0092-outside-workspace-approval.md)); external file access asks in default/acceptEdits, while explicit rules or bypass can allow it → `@cosmew/security` `evaluateRead` (deny → ask → allow) → approval via `CosmewClient.requestPermission` → audit (`tool_audit`) → execute → redact. Tools are offered only after `client.setToolsEnabled(true)` (the TUI does it on folder consent). Provider adapters only convert: malformed or unknown tool calls reach the ToolRouter, which answers the model (`INVALID_INPUT`/`UNKNOWN_TOOL`). `CosmewClient.requestPermission` applies the permission mode to `ask` decisions only; deny rules never change. `apps/cli/src/bootstrap/permission-settings.ts` owns the settings files (mtime-cached reads, hash-based trust, legacy-rule migration); `@cosmew/security` `settings.ts` is the pure parse/merge/trust logic. Grep uses a trusted ripgrep (absolute path outside the workspace, `--no-config`, results re-checked by `evaluateRead`) and falls back to a Worker with a hard deadline. `edit`/`write` ([ADR 0038](docs/adr/0038-claude-style-file-tools.md)) compile to the same patch plan as `apply_patch` and require the model to have read the file's current content (`ReadLedger`).

Startup gate behavior follows ADR 0086, which amends ADRs 0014 and 0075. The first interactive run presents the theme picker, optional sign-in and security notes. Folder consent is recorded once per canonical workspace. The TUI opens without credentials and verifies the selected account and model on the first send with a small, potentially billable request. Verification failure keeps the draft and offers account selection. Individual tools still require their own permissions. `cosmew exec` verifies before starting the turn. [ADR 0086](docs/adr/0086-first-run-onboarding.md) · [ADR 0075](docs/adr/0075-persistent-workspace-consent-and-claude-keybindings.md)

Compaction ([ADR 0054](docs/adr/0054-model-compaction.md), contract 1.26): at 85% of the usable window (ADR 0063) or on `/compact [focus]` / `client.compact()` (idle only), the current model writes a handoff summary; recent user messages (≤20k tokens), the plan and file-change receipts are kept, tool output of the span is dropped. Durable snapshot (`ContextSnapshot.strategy: 'model'`) before a turn's first round, in-memory mid-turn; any model failure falls back to the extractive checkpoint, cancellation changes nothing, the journal is never modified. Usage is counted; event `context.compacted`. `ConversationOptions.modelCompaction=false` disables the automatic model call and keeps the excerpt checkpoint. The user setting `autoCompact=false` skips both automatic checkpoints and keeps manual `/compact` available.

The user settings store also persists `verbose` (starts in the Ctrl+O transcript view with expanded tools and applies live) and `showTurnDuration` (controls the completed-turn timing line). The defaults are compact transcript view and visible turn duration. `/effort` and `/model` show SDK-resolved levels on all supported protocols, including Anthropic and Gemini budget controls (ADR 0090).

## Conventions specific to this repo

- Permission invariant (docs/architecture/dependency-rules.md): validate → normalize target → evaluate policy → persist intent → revalidate → execute → record. Nothing may bypass the permission engine, including builtin tools, plugins, MCP, SDK and recovery.
- Record new dependencies (name, version, license) in `docs/delivery/dependency-catalog.md` when adding them.
- Tests must be meaningful (invariants, cancellation, failure modes); do not use mock success to prove compatibility. Fixtures are in `tests/fixtures.ts`. Live provider verification is recorded separately from fixture evidence.
- Update docs in the same change (docs are mostly Vietnamese; ADR/acceptance files under `docs/delivery` record evidence). Upstream research must record URL/path, access date, revision and evidence limits; prefer "Needs verification" over guessing.
- Logs must be redacted; never commit credentials or sensitive prompt output.

## Wave 1 tools (ADRs 0040–0044)

- Product permissions follow ADR 0061 (see the first paragraph): default mode `default`, sandbox off, commands and edits asked under regular permissions (ADR 0081). A Bash prompt with the sandbox off focuses Yes and shows a dim `/sandbox` hint. With the sandbox on, an escape or exclusion warns about full user permissions and focuses No. Project deny/ask rules win; all rule changes revoke dispatcher/prompt session grants, restrictive changes also deny/settle pending prompts. Nonempty stdin follows the launch sandbox of its terminal (sandboxed: like a command of that kind; launched unsandboxed: asks; a terminal launched unsandboxed is refused once the sandbox is on again). Opaque complex shell scripts cannot match allow rules; dangerous-command detection is a display heuristic and the sandbox is the execution boundary.
- `read` supports paged directories, negative offsets, PNG/JPEG/GIF/WebP/PDF and notebooks. Media are size/structure checked and scanned for registered secrets as UTF-8 and latin1; minimal format checks are not full decoders and do not detect every compressed/encoded secret. Names and results are redacted. Nested AGENTS only comes from non-vendored/non-ignored approved directories, remains lower-trust user/project data and is remembered per session. Known `vision: unsupported` models get text notes; `vision: unknown` is tried (documented deviation from the original plan).
- `update_plan` stores at most 50 steps with at most one running step. Plan text is redacted before the state callback; SDK `plan()` and `plan.updated` drive the pinned checklist. `request_user_input` is offered only with an attached interactive UI; pending display text is sanitized, answers/dismissal are plain tool results, abort clears the dialog. Restart preserves answered history but never restores a live unanswered dialog.
- `lsp` offers nine read operations; `lsp_rename` authorizes the source read and compiles validated edits to the existing patch plan. Language servers are optional project/PATH binaries, started lazily through native `spawnService` in a read-only, no-network, secret-masked sandbox. No binary install or unsandboxed fallback. Authorized open files have a coalesced watcher; requests also resync. Successful write receipts may contain new ERROR diagnostics, shown under the edit. Comparison is message/source/code based, not full range-aware error tracking. TypeScript has real local native-sandbox verification; Python/Go/Rust and other OS remain Needs verification. See ADR 0043 and `COSMEW_TEST_REAL_LSP=1` test.
- `web_search` uses fixed Exa (keyless default), Tavily REST, Firecrawl or Parallel MCP endpoints, selected from host env keys. The CLI owns `WebSearchClient`, registers keys with the redactor and injects only a search port. It is audited and follows project rules; output is untrusted, bounded and redacted. User MCP connect (ADR 0068) is separate: stdio and HTTP from the user `mcp.json` only, through ToolDispatcher. OAuth, project config, tool_search and mcp_resource are not in that slice.
- `web_fetch` authorizes every origin/redirect through the dispatcher before DNS/socket work, checks all DNS answers and pins the chosen public address to the connection. Private/metadata destinations, ambient cookies/auth/proxies, binary/encoded responses, over-5-MiB bodies and over-five redirects are refused. Total deadline defaults 30 seconds, caps 120. Markdown/text remove active content; explicit HTML returns inert raw source. Never promote web/MCP output into host instructions.
- Subagents (ADR 0058, `@cosmew/agents`): `agent` runs a nested `Conversation` through the same `ToolDispatcher`/policy; children inherit the sandbox, permission mode and rules but only `fs.read` session grants (`SessionGrants.createChild`), never memories or user questions, tool sets only narrow (`explore`/`plan` read-only), `max_threads` 6 / `max_depth` 1 (`[agents]` in host config), over-limit calls are rejected like Codex. Child journals are hidden from `listSessions()`; events `subagent.started/progress/finished`.
- SDK observer events implemented: `plan.updated`, `question.asked/answered`. Diagnostics are receipt/transcript data; standalone `diagnostics.reported` and general `mcp.server.status` events remain unimplemented. Wave-1 evidence and limitations: `docs/delivery/wave-1/acceptance.md`, `web.md`, `continuation.md`.

Skills (S3, [ADR 0056](docs/adr/0056-skills-discovery-and-mediated-invocation.md)): lazy project/user/system catalog, `/skills`, `/name args` and `$name` (including exec); body reads use `skill` through ToolDispatcher, `allowed-tools` grants nothing. Only discovered skill resources get Seatbelt read access; state and outside-workspace writes stay protected.

Memories (S4, ADR 0057): user-only `~/.cosmew/projects/<sha256 canonical workspace>/memory/`, mediated `memory` CRUD, `/memory` Modal and SDK; `MEMORY.md` is untrusted project-context data, never model instructions. Disable with `COSMEW_MEMORY=0` or user `[memories] enabled = false`; S5 subagents must omit the memory context port. Memory reads track usage; oversized indexes rank by use/recency, stale notes are flagged after 30 days, and assistant memory citations render compactly. Auto extraction remains deferred/off.

Appearance ([ADR 0080](docs/adr/0080-user-settings-appearance.md)): CLI injects an
SDK AppearanceStore backed by user `settings.json`, preserving permission/sandbox
and unknown keys. Global SQLite appearance imports once without deleting it;
project JSON appearance is ignored and explicit project edits are session-only.
`/config` Theme opens the picker; `theme=` uses the same theme+mode normalization.
Daltonized/ANSI palette colors are intent-based: exact Claude parity Needs verification.
Startup onboarding remains unchanged by Tasks 1–2. Sandbox defaults and `/sandbox` controls now follow [ADR 0081](docs/adr/0081-sandbox-defaults-like-claude-code.md): false/false/true, existing explicit settings retained, recorded one-time startup notice otherwise.
