# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Hannes / FUTRYN is a TypeScript + Bun coding agent aiming at Codex / Claude Code / OpenCode parity. Any feature serving that goal may be built without per-feature authorization; record large design decisions as ADRs in `docs/adr/`. Implemented today: provider/auth (API adapters only; no external agent runtime), the FUTRYN TUI, the Codex-parity agent loop, workspace tools (`read`, `glob`, `grep`, `edit`, `write`, `apply_patch`, `exec_command`, `write_stdin`), durable recovery/compaction, extended read/media/notebooks/nested instructions, durable plans and interactive questions, sandboxed LSP/rename, public web search/fetch and the MCP HTTP search adapter (wave 1; contract 1.21 / SQLite 8). Not yet built: subagents, general MCP server management/stdio/OAuth, plugins, GUI; empty `packages/*` directories (`extensions`, `agents`, `compat-*`, `testkit`, empty builtin files under `tools`) and `apps/{server,web,desktop}` are placeholders, not evidence of features. Never claim "Product MVP complete": live authenticated generation is not verified.

`AGENTS.md` (Vietnamese) holds the agent rules. Permissions follow Codex: sandbox `read-only` / `workspace-write` / `danger-full-access` and approval `untrusted` / `on-request` / `never`, with writes inside the writable sandbox roots auto-approved as in Codex `assess_patch_safety`.

Terminal execution ([ADR 0034](docs/adr/0034-unified-exec-terminal-parity.md), [0035](docs/adr/0035-native-sandbox-default.md)): `exec_command`/`write_stdin` run under the native OS sandbox by default like Codex (macOS Seatbelt; Linux bubblewrap, untested; Windows refused), with Docker only via `FUTRYN_COMMAND_BACKEND=docker` (`none` disables). Modes via `FUTRYN_SANDBOX_MODE` (workspace-write default): live workspace, `.git` readable (workspace and parents) but never writable, Futryn state denied, home dir hidden, only localhost reachable unless a `network.connect` approval (ADR 0053), FSEvents allowed, tool caches (`npm_config_cache`, `XDG_*`, …) in a per-session scratch dir; secrets readable unless `FUTRYN_SANDBOX_HIDE_SECRETS=1`. macOS cannot confirm `setsid` descendants die (reported `unconfirmed`). A failing sandbox never falls back to unsandboxed execution; the only unsandboxed run is one command the user approved after the model sent `sandbox_permissions: "require_escalated"` (refused under `never`). Hermetic tests pin `FUTRYN_COMMAND_BACKEND=none` (`tests/preload.ts`); Docker tests need `FUTRYN_TEST_CONTAINER=1`.

## Commands

Requires Bun 1.4.4. No build step; Bun runs the TS workspace directly.

```sh
bun install --frozen-lockfile --ignore-scripts
bun run hannes            # CLI (apps/cli/src/index.ts); bare TTY opens TUI; exec <prompt|-> --cd <dir> runs headlessly (contract 1.24)
bun run futryn            # full-screen TUI (same as `hannes tui`)
bun run typecheck         # tsc --noEmit
bun run lint              # tsc with noUnusedLocals/Parameters + prettier --check + git diff --check
bun run format            # Prettier 3.9.10 (.prettierrc.json) on all .ts/.tsx/.js; run before committing
bun test tests            # all tests
bun test tests/contracts/theme-engine.test.ts          # single file
UPDATE_GOLDEN=1 bun test tests/contracts/tui-golden.test.ts   # re-record rendered frames; review the diff first
bun test tests/contracts -t "name substring"           # single test by name
bun run test:integration  # provider adapters + tests/security
bun run test:e2e          # tests/end-to-end (PTY/CLI flows)
```

Optional, touches real OS keyring / network (opt-in via env): `HANNES_VERIFY_KEYRING=1 bun scripts/verify-keyring.ts`, `HANNES_TEST_KEYRING=1 bun test tests/end-to-end/provider-cli.test.ts`, `HANNES_LIVE_PUBLIC=1 bun scripts/smoke-public-catalogs.ts`. `model doctor --generate` makes a billable request.

## Architecture

Workspace packages (`@futryn/*`, resolved via bun workspaces, `moduleResolution: bundler`): `contracts`, `models`, `security`, `persistence`, `core`, `sdk`, `tools`, `workspace`, `code-intel`, `mcp`, `apps/tui`, `apps/cli`.

Dependency rules ([docs/architecture/dependency-rules.md](docs/architecture/dependency-rules.md)) are a DAG enforced by review, not tooling:
- Every package may depend on `contracts`; `contracts` depends on no Hannes package and exports no foreign SDK types.
- `core`, `models`, `security`, `persistence`, `sdk`, `workspace` depend on nothing else in Hannes. They meet only through injected ports. `tools` may depend on `workspace`, `security` and `code-intel`; `code-intel` may depend on `workspace`. `mcp` is a transport adapter injected by the CLI; tools never imports its implementation.
- `apps/tui` depends on `sdk` only (UI talks command/event protocol). `apps/cli` is the **composition root**: it is the only place that wires models + security + persistence + core + tools + workspace + tui (`apps/cli/src/bootstrap/startup.ts` builds the `Application`).
- Never deep-import another package's `src/` files; use its `index.ts`. Public contract changes need an ADR + migration/versioning + consumer updates.

Ownership: `core` orchestrates (agent loop in `packages/core/src/agent`, context builder); `security` decides permissions, holds secrets/OAuth and audit; `persistence` owns all durable SQLite writes (`~/.hannes/provider-auth.sqlite`); `models` only adapts provider wire formats (`providers/{anthropic,openai-compatible,router9}`, catalog, streaming, usage); adapters convert, never decide.

Credentials: API keys live in separate OS keyring entries or as environment-variable *references*; there is no plaintext fallback. Failed/cancelled logins must remove stored credentials. Account/provider switching starts fresh context (see ADR 0009 for the continuation rules).

Provider sign-in and execution ownership ([ADR 0045](docs/adr/0045-remove-delegated-and-chat-only-runtimes.md)-[0049](docs/adr/0049-remove-codex-runtime.md)): Futryn only calls provider APIs and reads responses; every model runs the Futryn agent loop with Futryn tools (`executionBackendFor`: `hannes`, or `chat-only` without folder consent). No external agent process exists: no `delegated`/`codex-bridge` backend, no Codex/Copilot/Gemini/Qwen/Grok runtime (v7 and v8 migrations delete their accounts and credentials; startup deletes leftover `runtime-tmp`). A provider stream can never report a tool result. ChatGPT signs in only through the direct API (`apps/cli/src/subscriptions/chatgpt-oauth.ts`, OAuth + PKCE, tokens in the keyring; live behavior unverified). Any other endpoint is added by the user-level `~/.futryn/config.toml` `[model_providers.<id>]` (Codex field names; parsed in `packages/models/src/host-config.ts`, loaded by `apps/cli/src/bootstrap/host-config.ts`; never read from a workspace, no plaintext tokens, token command without a shell). `status().toolsEnabled`/`availableTools()` are true only when the backend runs Futryn tools.

TUI (`apps/tui/src`, see [ADR 0015](docs/adr/0015-tui-feature-modules.md)): `app.tsx` is only the composition root. Each function is a folder under `features/<name>/` with `types.ts` (state), `logic.ts` (pure functions), `view.ts` (rendering), `controller.ts` (keys + state) and `index.ts` (only public entry). Features never import the app; they get a `TuiHost` from `core/feature.ts`, and cross-feature flows go through `host.features` (`AccountWorkflow`, `ModelWorkflow`). Overlays implement `OverlayFeature` and are registered in `FutrynTuiApp.registerFeatures`. Shared UI lives in `ui/` (`Modal` for dialog frames, `Canvas`, list/text-field helpers); build new dialogs with `Modal` rather than hand-assembling borders. Import from `@futryn/tui` (the `src/index.ts` barrel), not `src/app`. Transcript items record `parts` in arrival order (reasoning / text / tool groups, [ADR 0021](docs/adr/0021-codex-style-activity-presentation.md)) and render Claude Code style: `> prompt`, `✻ Thought`, `⏺ Bash(cmd)` + `⎿ output`, `⏺ answer` ([ADR 0028](docs/adr/0028-claude-style-transcript-and-permission-rules.md)). `/permissions` with nothing pending manages per-project Allow/Ask/Deny rules (`Bash(npm test:*)`, `Read(src/**)`) and the session mode; rules answer only `ask` decisions, deny > ask > allow > mode. Slash commands are canonical per ADR 0013 (`SLASH_COMMANDS`, shared by autocomplete and CLI help) and routed by `features/commands`; unsupported backends must print an explicit "Not implemented" diagnostic instead of faking success.

Tools (TOOLS1): `core`'s `Conversation` runs the Codex-parity loop ([ADR 0033](docs/adr/0033-codex-parity-agent-loop.md); no default round/call ceiling per ADR 0030, only user budgets and named safety limits) over an injected `ToolPort`: complete tool calls are dispatched while the response streams, shared/exclusive by the descriptor's explicit `parallel` flag (`core/agent/tool-runtime.ts`), and results are recorded in model-output order; `Conversation.steer`/`FutrynClient.submitWhileBusy` queue durable user input into the running turn (preempting the response being sampled; input a turn cannot deliver carries into the next turn), and sends shared exploration guidance from `core/agent/guidance.ts` via `ModelRequest.instructions` (system/developer channel; never repository text). `@futryn/tools`' `ToolDispatcher` is the only enforcement point: validate → `@futryn/workspace` resolves the path inside the root (outside is denied) → `@futryn/security` `evaluateRead` (deny → ask → allow) → approval via `FutrynClient.requestPermission` → audit (`tool_audit`) → execute → redact. Tools are offered only after `client.setToolsEnabled(true)` (the TUI does it on folder consent). Provider adapters only convert: malformed or unknown tool calls reach the ToolRouter, which answers the model (`INVALID_INPUT`/`UNKNOWN_TOOL`). `FutrynClient.requestPermission` applies the permission mode to `ask` decisions only; deny rules never change. Grep uses a trusted ripgrep (absolute path outside the workspace, `--no-config`, results re-checked by `evaluateRead`) and falls back to a Worker with a hard deadline. `edit`/`write` ([ADR 0038](docs/adr/0038-claude-style-file-tools.md)) compile to the same patch plan as `apply_patch` and require the model to have read the file's current content (`ReadLedger`).

Startup gate (ADR 0014): the TUI requires per-session workspace-folder consent, then verifies the selected account/model with a small (possibly billable) request; on failure the user picks another account or signs in.

## Conventions specific to this repo

- Permission invariant (docs/architecture/dependency-rules.md): validate → normalize target → evaluate policy → persist intent → revalidate → execute → record. Nothing may bypass the permission engine, including builtin tools, plugins, MCP, SDK and recovery.
- Record new dependencies (name, version, license) in `docs/delivery/dependency-catalog.md` when adding them.
- Tests must be meaningful (invariants, cancellation, failure modes); do not use mock success to prove compatibility. Fixtures are in `tests/fixtures.ts`. Live provider verification is recorded separately from fixture evidence.
- Update docs in the same change (docs are mostly Vietnamese; ADR/acceptance files under `docs/delivery` record evidence). Upstream research must record URL/path, access date, revision and evidence limits; prefer "Needs verification" over guessing.
- Logs must be redacted; never commit credentials or sensitive prompt output.


## Wave 1 tools (ADRs 0040–0044)

- Product approval defaults to `on-request` (`auto` UI mode), configured through `FUTRYN_APPROVAL_POLICY=untrusted|on-request|never`; commands and edits inside the configured writable sandbox may run automatically. Project deny/ask rules win. All rule changes revoke dispatcher/prompt session grants; restrictive changes (adding deny/ask or removing allow) also deny/settle pending prompts without changing session mode. Adding allow keeps the current “don’t ask again” prompt resolvable. `on-request`/`never` run every non-dangerous command inside the sandbox, including scripts the parser cannot split and non-empty stdin input; `untrusted` asks. Opaque complex shell scripts cannot match allow rules; dangerous-command detection is a heuristic and the sandbox remains the actual execution boundary. Sandbox and approvals follow Codex exactly (ADR 0053 supersedes ADR 0040's stricter-than-Codex stdin and unverified-command rules).
- `read` supports paged directories, negative offsets, PNG/JPEG/GIF/WebP/PDF and notebooks. Media are size/structure checked and scanned for registered secrets as UTF-8 and latin1; minimal format checks are not full decoders and do not detect every compressed/encoded secret. Names and results are redacted. Nested AGENTS only comes from non-vendored/non-ignored approved directories, remains lower-trust user/project data and is remembered per session. Known `vision: unsupported` models get text notes; `vision: unknown` is tried (documented deviation from the original plan).
- `update_plan` stores at most 50 steps with at most one running step. Plan text is redacted before the state callback; SDK `plan()` and `plan.updated` drive the pinned checklist. `request_user_input` is offered only with an attached interactive UI; pending display text is sanitized, answers/dismissal are plain tool results, abort clears the dialog. Restart preserves answered history but never restores a live unanswered dialog.
- `lsp` offers nine read operations; `lsp_rename` authorizes the source read and compiles validated edits to the existing patch plan. Language servers are optional project/PATH binaries, started lazily through native `spawnService` in a read-only, no-network, secret-masked sandbox. No binary install or unsandboxed fallback. Authorized open files have a coalesced watcher; requests also resync. Successful write receipts may contain new ERROR diagnostics, shown under the edit. Comparison is message/source/code based, not full range-aware error tracking. TypeScript has real local native-sandbox verification; Python/Go/Rust and other OS remain Needs verification. See ADR 0043 and `FUTRYN_TEST_REAL_LSP=1` test.
- `web_search` uses fixed Exa (keyless default), Tavily REST, Firecrawl or Parallel MCP endpoints, selected from host env keys. The CLI owns `WebSearchClient`, registers keys with the redactor and injects only a search port. It is audited and follows project rules; output is untrusted, bounded and redacted. General MCP tool/server discovery, stdio/OAuth and `/mcp` are W12, not implemented by this adapter.
- `web_fetch` authorizes every origin/redirect through the dispatcher before DNS/socket work, checks all DNS answers and pins the chosen public address to the connection. Private/metadata destinations, ambient cookies/auth/proxies, binary/encoded responses, over-5-MiB bodies and over-five redirects are refused. Total deadline defaults 30 seconds, caps 120. Markdown/text remove active content; explicit HTML returns inert raw source. Never promote web/MCP output into host instructions.
- SDK observer events implemented: `plan.updated`, `question.asked/answered`. Diagnostics are receipt/transcript data; standalone `diagnostics.reported` and general `mcp.server.status` events remain unimplemented. Wave-1 evidence and limitations: `docs/delivery/wave-1/acceptance.md`, `web.md`, `continuation.md`.
